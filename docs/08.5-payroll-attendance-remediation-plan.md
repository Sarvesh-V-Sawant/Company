## Decision Gates

This document contains two binary decisions that determine scope and remediation volume. Both must be resolved before implementation begins.

## Decision Gate 1 — Late Arrival Policy (BR-002)

### Option A: Scope In (Late Arrival Policy Engine)

Add a documented late arrival policy with grace period and optional penalty.

**Schema changes to `companySettings`:**
```typescript
// Rename existing field:
sessionAutoClosePaddingMinutes: number; // was: gracePeriodMinutes
                                         // minutes after workEndTime before cron auto-closes sessions

// Add new fields:
lateArrivalGraceMinutes: number;         // minutes after workStartTime before check-in is flagged late (default: 0)
lateMarkingPolicy: 'none' | 'flag-only'; // v1: flag-only (no pay deduction — informational)
```

**Schema changes to `attendanceDays`:**
```typescript
isLateArrival: boolean;    // true if checkIn.timestamp > workStartTime + lateArrivalGraceMinutes
lateByMinutes: number;     // how many minutes late (0 if not late)
```

**API changes:**
- `POST /api/v1/attendance/checkin` response: rename `flags.outsideGracePeriod` → `flags.isLateArrival`; document its meaning.
- `GET /api/v1/settings` admin response: include `lateArrivalGraceMinutes`, `sessionAutoClosePaddingMinutes`.
- `GET /api/v1/attendance/history` response: include `isLateArrival`, `lateByMinutes` per day.

**UI changes:**
- Admin Settings: rename "Grace Period" field; add "Late Arrival Grace" field.
- Admin Attendance view: show "Late" badge on attendance day rows where `isLateArrival: true`.
- Mobile Attendance: check-in confirmation shows "You checked in 12 minutes late" if `isLateArrival: true`.

**Pay deduction:** NOT included in v1. Late arrival is informational only (`flag-only`). A `lateMarkingPolicy: 'half-day-after-N'` variant can be added in v2 if needed.

### Option B: Scope Out (Explicitly Out of v1)

Document that late arrival tracking is a v2 feature. Fix the current ambiguity only.

**Required fixes:**
1. Rename `gracePeriodMinutes` → `sessionAutoClosePaddingMinutes` in `companySettings` schema, API spec, and settings UI. Update the DB comment. (One rename across 3 docs.)
2. Remove `flags.outsideGracePeriod` from the `POST /api/v1/attendance/checkin` response (it has no documented meaning). Replace with `flags.isLateCheckIn: false` (always false in v1) or remove entirely.
3. Add note to `docs/02-database-design.md` §9 companySettings constraints: "Late arrival policy not implemented in v1. `sessionAutoClosePaddingMinutes` is exclusively for session auto-close cron timing."

**Recommendation:** **Option B** for v1. The ambiguity is easily fixed. Late arrival tracking with deductions is a complex policy feature that varies by company — better to do it right in v2 with full employer requirements than to ship an incomplete v1 version.

## Decision Gate 2 — Salary Components (BR-003)

### Option A: Keep Flat Salary Model (Recommended for v1)

Document explicitly that the system uses a single `monthlySalary` (gross) with no component breakdown. Payslip shows Gross Salary, Deductions, and Net Payable.

**Changes required:**
1. Relabel `monthlySalary` → displayed as "Gross Salary" in API responses and UI (field name stays, display label changes).
2. Relabel `payableAmount` → displayed as "Net Payable" in API responses and UI.
3. Add `deductionBreakdown` object to `payrollSummaries` and API response (see BR-004 section below) to show LWP deduction and absent deduction separately — no component overhead.
4. Document "Salary Components: Out of Scope v1 — by design. System uses flat gross salary." in `docs/08.4`.

**No schema changes. No formula changes.**

**Recommendation:** **Option A** for v1. Flat salary model is consistent, complete, and correct for the current design. Adding components (Basic %, HRA %, etc.) is a significant extension that requires employer-specific configuration and is better introduced after v1 launches with real usage data.

### Option B: Add Salary Components (High Impact)

Add a structured component breakdown to `companySettings`, `users`, `payrollSummaries`, API, and both UIs.

**Schema changes to `companySettings`:**
```typescript
salaryComponents: {
  basicPercent: number;        // % of monthlySalary (e.g. 50)
  hraPercent: number;          // % of monthlySalary (e.g. 20)
  allowances: Array<{
    name: string;
    amount: number;            // fixed amount OR percent
    isPercent: boolean;
  }>;
};
```

**Schema changes to `payrollSummaries`:**
```typescript
componentBreakdown: {
  basic: number;
  hra: number;
  allowances: Array<{ name: string; amount: number; }>;
  bonus: number;               // optional; per-compute override
  grossSalary: number;         // sum of all earning components
  lwpDeduction: number;        // LWP portion of deductions
  absentDeduction: number;     // absent portion of deductions
  lateDeduction: number;       // late penalty (v2 — 0 in v1)
  totalDeductions: number;     // = lwpDeduction + absentDeduction + lateDeduction
  netPayable: number;          // = grossSalary - totalDeductions
};
```

**Impact:** DB schema changes (payrollSummaries, companySettings), API changes (5+ endpoints), admin payslip UI redesign, mobile payslip UI (new), settings UI additions. Estimated scope: ~3–4 additional days of planning + specification work before any code is written.

**Recommendation:** **Option A** for v1. Revisit Option B post-launch.

### REM-003 — `gracePeriodMinutes` Ambiguity Fix (BR-002 Option B)

**Priority: HIGH** (required regardless of Option A/B choice)
**Target docs: `docs/02-database-design.md`, `docs/04-api-specification.md`**

#### If choosing Decision Gate 1 Option B (Scope Out):

**1. Rename in `docs/02-database-design.md` §9 (`companySettings`):**
```typescript
// Before:
gracePeriodMinutes: number; // minutes after workEndTime before midnight-rollover cron closes sessions

// After:
sessionAutoClosePaddingMinutes: number; // minutes after workEndTime before midnight-rollover cron closes active sessions. NOT a late-arrival grace period — late arrival policy is out of scope v1.
```

**2. Update `docs/04-api-specification.md`:**
- §11.1 Settings GET response: rename `gracePeriodMinutes` → `sessionAutoClosePaddingMinutes`.
- §11.2 Settings PUT request: rename field.
- §5.1 Check-in response: remove `flags.outsideGracePeriod` OR rename to `flags.isOutsideSessionWindow` with note "informational only — no policy effect in v1."

**3. Update validation in §11.2:** `sessionAutoClosePaddingMinutes: 0–120`

#### If choosing Decision Gate 1 Option A (Scope In):

Follow the full Option A schema in Decision Gate 1. `gracePeriodMinutes` becomes `sessionAutoClosePaddingMinutes` + new `lateArrivalGraceMinutes` field added.
