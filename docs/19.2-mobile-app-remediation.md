### H2 — Token Refresh Missing `sessionId` ✅ RESOLVED

- `SecureStorageService.clearSession()` clears `sessionId`.
- `AuthRepository.login()` extracts `data['sessionId']` and saves it.
- `AuthRemoteSource.refresh(token, sessionId)` — signature updated.

- `AuthRemoteSource.logout(sessionId)` sends `sessionId` per spec.

### H4 — FCM / Push Notifications ✅ RESOLVED

- `firebase_core: ^3.3.0`, `firebase_messaging: ^15.1.0`, `flutter_local_notifications: ^17.2.2` added to `pubspec.yaml`.
- `main.dart`: `Firebase.initializeApp()`, background message handler registered, high-importance Android notification channel created.
- `FcmService` (`lib/features/notifications/data/services/fcm_service.dart`):
  - `initialize()` — wires foreground + tap handlers. **Called in `main()` before `runApp`.**
  - `registerToken()` — calls `POST /api/v1/notifications/fcm-token` with `{token, deviceId, platform}` per spec 9.4; registers `onTokenRefresh` listener.

**Deployment prerequisite:** `google-services.json` must be placed at `android/app/google-services.json` before `flutter build apk`.

### H5 — Device Fingerprint Missing 4th Identifier ✅ RESOLVED

```dart
// Before (3-field — spec deviation)
final raw = '${android.id}|${android.model}|${android.brand}';

// After (4-field — spec formula)
final raw = '${android.id}|${android.model}|${android.brand}|${android.serialNumber}';
```

`android.serialNumber` is the closest stable hardware identifier available in `device_info_plus` 10.x as a substitute for `androidId` (removed from the package). Hash is cached in `SecureStorage` so existing installed devices are unaffected across app sessions; only fresh installs compute the new 4-field hash.

**Known constraint:** Admin-registered device hashes must use the same formula. Existing 3-field hashes require device re-registration.
