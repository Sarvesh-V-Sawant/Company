## LOW Findings

### SV-001 — `tsconfig.json` auto-modified by Next.js build
**Severity:** LOW  
**Impact:** None — the changes are correct  
**Detail:** `npm run build` caused Next.js to auto-update `tsconfig.json`:
- `jsx: "preserve"` → `jsx: "react-jsx"` (Next.js App Router requires react-jsx)
- `.next/dev/types/**/*.ts` added to `include`

**Disposition:** No action needed. These changes are expected and correct for Next.js App Router. The original spec (`jsx: "preserve"`) was incorrect for App Router — Next.js fixed it automatically.

### SV-002 — `apps/mobile/.env.example` (non-JSON) not present
**Severity:** LOW  
**Impact:** None — the JSON version exists and is the correct format  
**Detail:** `docs/08-project-scaffolding.md` Section 1.3 tree lists `.env.example` for mobile, but Section 3.4 (Flutter Environment Strategy) specifies `.env.example.json`. The `.env.example.json` is present and correct (Flutter uses `--dart-define-from-file` which requires JSON format).  

**Disposition:** `.env.example.json` is the correct file. The tree listing was inconsistent with the spec body. No action needed.

### SV-003 — `scripts/migrations/runner.ts` is a `.gitkeep`-only directory
**Severity:** LOW

**Detail:** `scripts/migrations/` directory exists but contains only `.gitkeep`. The `runner.ts` entry point (required for `npm run migrate` / `npm run migrate:rollback`) is not yet scaffolded. This is S-SC-006 from the prior review.

## Specification Deviation Notes

### SD-001 — `src/middleware.ts` → `src/proxy.ts` (Next.js 16 Breaking Change)
**Type:** Spec deviation required by framework version  
**Impact:** HIGH if not fixed (auth guard silently deprecated)  
**Detail:** All approved spec documents (`docs/08-project-scaffolding.md`, `docs/08.2-scaffolding-remediation.md`) specify `src/middleware.ts` with `export async function middleware()`. Next.js 16.2.9 introduced `proxy.ts` as the replacement. The `middleware` file convention is deprecated and will be removed in a future minor/major version.

**Resolution applied:** `src/proxy.ts` with `export async function proxy()`. All behavior identical. Auth guard chain unchanged.

**Note for future docs:** All references to `middleware.ts` in specification documents should be updated to `proxy.ts` before Phase 2 begins. Phase 2 spec docs should use the `proxy` convention.

---

### SD-002 — `eslint-config-next` v16 uses native flat config (not legacy)
**Type:** Spec deviation required by package version  
**Impact:** Lint completely broken without fix  
**Detail:** The spec does not specify ESLint config format. `eslint-config-next` v16.2.9 exports a native ESLint 9 flat config array, not a legacy config object. Using `FlatCompat` with it causes a circular JSON serialization error.

**Resolution applied:** `eslint.config.mjs` now imports `eslint-config-next` as a native flat config array.
