## H3 — Path: Change Password + Proxy Guard

**Finding:** Implementation at `PATCH /api/v1/auth/me/password`; spec at `PATCH /api/v1/auth/me/change-password`. `proxy.ts` `PASSWORD_CHANGE_ALLOWED` also hardcoded the wrong path, meaning users stuck in `requiresPasswordChange: true` state could not reach the change-password endpoint through the proxy.

**Fix:**
1. Deleted `src/app/api/v1/auth/me/password/` directory.
2. Created `src/app/api/v1/auth/me/change-password/route.ts` with identical logic + `dynamic = 'force-dynamic'`.
3. Updated `src/proxy.ts` `PASSWORD_CHANGE_ALLOWED`: `/api/v1/auth/me/password` → `/api/v1/auth/me/change-password`.

**Proxy guard verified:** Paths allowed during `requiresPasswordChange: true`:
```typescript
const PASSWORD_CHANGE_ALLOWED = [
  '/change-password',             // UI page
  '/api/v1/auth/me/change-password',  // ✅ fixed
  '/api/v1/auth/logout',
  '/api/v1/auth/me',
];
```

**Files changed:**
- `src/app/api/v1/auth/me/password/route.ts` — **deleted**
- `src/app/api/v1/auth/me/change-password/route.ts` — **created**
- `src/proxy.ts` — **updated** (`PASSWORD_CHANGE_ALLOWED`)

## H4 — FCM Token: Path, Method, Schema

**Finding:** Four simultaneous deviations:
1. Wrong path: `PATCH /api/v1/auth/me/fcm-token` vs spec `POST /api/v1/notifications/fcm-token`
2. Wrong HTTP method: PATCH vs POST
3. Wrong request field: `deviceFingerprint` + `deviceInfo` vs spec `deviceId`
4. Wrong upsert key: `{ employeeId, deviceFingerprint }` vs spec BR-NOT-03 `{ employeeId, deviceId }`

**Fix:**
1. Deleted `src/app/api/v1/auth/me/fcm-token/` directory.
2. Created `src/app/api/v1/notifications/fcm-token/route.ts` as `POST`, using updated schema.
3. Renamed `UpdateFcmTokenSchema` → `RegisterFcmTokenSchema` in `src/validators/auth.ts`; replaced fields `{ token, deviceFingerprint, deviceInfo, platform }` → `{ token, deviceId, platform }`.
4. Updated `AuthService.updateFcmToken()`: removed `deviceFingerprint` and `deviceInfo` params, added `deviceId`; upsert key now `{ employeeId, deviceId }` (BR-NOT-03).
5. Updated `src/models/FcmToken.ts`: field `deviceFingerprint` → `deviceId`; removed `deviceInfo` field entirely; updated index from `deviceFingerprint` → `deviceId`.

**New request body (aligned with spec §9.4):**
```json
{
  "token": "string",
  "deviceId": "string",
  "platform": "android | ios"
}
```

**Files changed:**
- `src/app/api/v1/auth/me/fcm-token/route.ts` — **deleted**
- `src/app/api/v1/notifications/fcm-token/route.ts` — **created**
- `src/validators/auth.ts` — `UpdateFcmTokenSchema` renamed to `RegisterFcmTokenSchema`; schema updated
- `src/services/AuthService.ts` — `updateFcmToken()` signature updated
- `src/models/FcmToken.ts` — `deviceFingerprint` → `deviceId`; `deviceInfo` removed
