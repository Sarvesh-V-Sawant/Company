## 3. Authorization & Ownership

**JWT validation:** `getAuthUser` uses `jose.jwtVerify` — cryptographically verified. Supports both `Authorization: Bearer` header and `__session` cookie. Throws `AuthError` with HTTP 401 on failure.

**Ownership matrix:**

| Operation | Enforcement |
|---|---|
| List | `Notification.find({ employeeId: userId })` |
| Mark single read | `findOneAndUpdate({ _id, employeeId })` — returns null (→ 404) if different user's notification |
| Mark all read | `updateMany({ employeeId })` + optional `_id: { $in: ids }` |
| FCM token | `findOneAndUpdate({ employeeId, deviceId })` upsert |

No privilege escalation paths found.

## 8. Pagination & Filtering

**Pagination:** page/limit via `NotificationListQuerySchema` (page ≥ 1, limit 1–100, default 20). Returns `{ data, meta: { page, limit, total, totalPages } }`. GET route uses `NextResponse.json({ success: true, ...result })` directly (not `success()` util) to preserve the `meta` field — correct pattern per payroll list precedent.

**Filtering:**
- `isRead`: coerced from string `'true'`/`'false'` to boolean
- `type`: API kebab-case → DB camelCase via `API_TO_TYPE` reverse map. Unknown type sets `filter.type = null` → zero results (no error thrown — correct)

## 10. Findings

### HIGH
_None._

### MEDIUM

**M1 — Two notification types defined but never triggered**  
`attendanceReminder` and `passwordReset` appear in `NotificationType` enum and `TYPE_TO_API` map but no service calls them. No cron job triggers attendance reminders; `forgot-password` and `reset-password` routes were deleted in a previous phase.  
**Impact:** Dead enum values — minor type surface inflation. Could confuse future developers or clients filtering by `type=attendance-reminder`.  
**Recommendation:** Remove unused types from enum and map, or add a comment noting planned-but-not-yet-implemented status.

**M2 — No integration tests for notification endpoints**  
All 4 HTTP routes lack endpoint-level tests. Functional correctness is only validated at the service unit-test layer.  
**Impact:** Regression risk on route-layer logic (body parsing, auth wiring, schema validation).  
**Recommendation:** Add integration tests in a future quality pass alongside other untested routes.

### LOW

**L1 — markAllRead without `ids` marks ALL user notifications in one updateMany**  
No upper-bound batching. For a user with thousands of notifications, a single `updateMany` could be slow.  
**Impact:** Negligible at current scale (internal tool). MongoDB compound index `{ employeeId, isRead }` mitigates.

**L2 — Email HTML template is bare `<p>${body}</p>`**  
No unsubscribe link, no company branding, no plain-text fallback.  
**Impact:** Email deliverability may be affected; not a functional defect.
