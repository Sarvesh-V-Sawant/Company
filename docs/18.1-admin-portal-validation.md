## 4. Findings

### 4.1 HIGH Findings

> **HIGH findings exist — STOP. Portal is not ready for Phase 11.**

---

#### H-01 — Missing Attendance Sub-Views (Screens #16, #17)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §4` — Requires `/attendance/weekly` (week-grid view) and `/attendance/monthly` (month-summary view) as distinct routes.  
**Implementation:** Only `/attendance` (daily list) and `/attendance/[id]` exist. Weekly and monthly views not implemented.  
**Impact:** Admin cannot see week-over-week grid or monthly summary — core attendance management capability missing.

---

#### H-02 — Missing Payroll Finalize / Unfinalize Actions (Screens #29, #30)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §9.4, §9.5` — Payroll rows must have Finalize (locks payroll, `PATCH /payroll/:id/:yearMonth/finalize`) and Unfinalize (with reason textarea, `PATCH /payroll/:id/:yearMonth/unfinalize`) modals. Once finalized, payroll is locked for payslip export.  
**Implementation:** Payroll list has no row actions. No finalize/unfinalize modals exist anywhere.  
**Impact:** Admin cannot finalize payroll — payroll module is read-only and functionally incomplete.

---

#### H-03 — Missing Payslip Detail Page (Screen #28)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §9.3` — `/payroll/[yearMonth]/[id]` shows individual payslip: breakdown of earnings/deductions, finalize/unfinalize buttons, export payslip PDF.  
**Implementation:** `/payroll/[month]/[year]` shows a month-level list of all employees for a period — not a payslip. Route concept is different. Payslip detail never rendered.  
**Impact:** No per-employee payslip view. No payslip export.

---

#### H-04 — Missing Payroll Stale Banner + Conflict Resolution Wizard (Screens #26, #27)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §9.6` — Post-leave-revocation workflow: stale banner at top of payroll list, `⚠ Stale` row badge, 3-step `PayrollReopenModal` (Unfinalize → Recompute → Re-finalize).  
**Implementation:** None of this exists.  
**Impact:** Admins cannot resolve payroll conflicts after leave revocation — data integrity gap.

---

#### H-05 — Missing Leave Balances Page (Screen #21)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §6.3` — `/leave/balances` shows all employees' leave balances: Paid/Sick/Casual quotas, used, remaining, carried-forward. API: `GET /leaves/balance`.  
**Implementation:** No `/leaves/balances` or `/leave/balances` page exists.  
**Impact:** Admin cannot view or manage leave balances — key HR function missing.

---

#### H-06 — Missing Audit Log Detail Page (Screen #36)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §12.2` — `/audit-logs/[id]` shows full event detail with `before`/`after` JSON diff rendered in amber-highlighted code blocks.  
**Implementation:** No `src/app/(portal)/audit-logs/[id]/` directory. List rows have no click-through navigation.  
**Impact:** Compliance/investigation tool is half-built — admins can list events but cannot inspect what changed.

---

#### H-07 — Payroll Compute: 6-State Modal Replaced with Basic ConfirmDialog (Screen #25)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §9.2` — 6-state modal: Idle → Validating → Computing → Partial Success → Success → Error. Shows per-employee computation status, error details, retry option.  
**Implementation:** `ConfirmDialog` with single `"This will compute payroll for YYYY-MM. Continue?"` message and a loading spinner. No per-employee status, no validation step, no error recovery.  
**Impact:** No visibility into payroll computation progress or per-employee errors.

---

#### H-08 — Route Naming Mismatch (Systemic)
**Severity:** HIGH  
**Spec:** `/leave`, `/leave/history`, `/leave/balances`, `/regularization`, `/regularization/history`  
**Implementation:** `/leaves`, `/leaves/[id]`, `/regularizations`, `/regularizations/[id]`  
**Impact:** Sidebar links, breadcrumbs, dashboard quick-action links (`/leaves?status=pending`, `/regularizations?status=pending`), and all internal `router.push()` calls use the wrong URL structure relative to the spec. Any URL bookmark or external link will break when routes are renamed to match spec.

---

#### H-09 — Missing `/unauthorized` Page + Middleware (Screen #45, §15.4–§15.6)
**Severity:** HIGH  
**Spec:** `docs/05-admin-ui-ux.md §15.5–§15.6` — Middleware enforces maintenance mode, forced password-change guard, unauthenticated redirect, role guard. `/unauthorized` page shown for non-admin role.  
**Implementation:** `src/middleware.ts` was deleted during Phase 10. `src/app/unauthorized/` does not exist. Role guard only in client-side layout (bypassable). Maintenance mode not enforceable.  
**Impact:** Security gap — role enforcement is client-side only. Maintenance mode cannot be activated. `/unauthorized` page missing entirely.

---

#### M-02 — Leave Pending/History Not Split Into Separate Routes
**Severity:** MEDIUM

**Implementation:** Single `/leaves` page with status filter. No revoke action visible.  
**Notes:** Combined view with filter is functionally adequate for Phase 10 scope. Leave revocation (`PATCH /leaves/:id/cancel`) is in the API but no UI trigger exists.

**Severity:** MEDIUM  
**Spec:** `/regularization` (pending queue) and `/regularization/history` (all records).  
**Implementation:** Single `/regularizations` page with status filter.

**Implementation:** Implementation not inspected in detail but no unread-dot or background-elevation CSS is evident from the notifications page structure. Individual notification `onClick` mark-as-read behavior needs verification.
