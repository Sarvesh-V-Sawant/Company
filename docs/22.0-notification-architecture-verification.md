## 3. Database Technology

**MongoDB Atlas is and remains the sole system database.**

| Concern | Technology | Role |
|---------|-----------|------|
| All business data | MongoDB Atlas | Primary store (replica set, transactions) |
| FCM tokens | MongoDB (`FcmToken` model) | Stored in MongoDB, not Firebase |
| Notifications | MongoDB (`Notification` model) | Persisted in MongoDB before delivery |
| Sessions, users, payroll, leave, attendance | MongoDB | All Mongoose models |
| Firebase | Firebase Admin SDK only | Push delivery channel — no data storage |

Firebase stores nothing. It is a delivery mechanism only.

---

## 4. Notification Technology

**Push notifications use Firebase Cloud Messaging (FCM) exclusively.**

| Component | Approved |
|-----------|---------|
| Backend push delivery | Firebase Admin SDK (`firebase-admin`) |
| Mobile push receipt | `firebase_messaging ^15.1.0` |
| Foreground display | `flutter_local_notifications ^17.2.2` |
| Token registration endpoint | `POST /api/v1/notifications/fcm-token` |
| Token storage | MongoDB `FcmToken` collection |
| Push delivery path | Backend → Firebase Admin SDK → FCM → device |

## 5. Required Firebase Infrastructure

The following are **required by the approved design** — not optional:

### Backend (server-side)
| Requirement | Source |
|-------------|--------|
| Firebase project created | Architecture doc — per-client isolation |
| Firebase Admin SDK credentials | `FIREBASE_PROJECT_ID`, `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY` env vars |
| FCM enabled in Firebase Console | Required for Admin SDK push calls |

### Mobile (Flutter build-time)
| File | Path | Required By |
|------|------|------------|
| `google-services.json` | `apps/mobile/android/app/google-services.json` | Android Firebase integration (build-time) |
| `firebase_options.dart` | `apps/mobile/lib/firebase_options.dart` | `Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)` in `main.dart` |
| `GoogleService-Info.plist` | `apps/mobile/ios/Runner/GoogleService-Info.plist` | iOS Firebase integration (build-time) |

These files are generated by `flutterfire configure` from a live Firebase project. They are not source-authored files — they cannot be written by hand. They are absent because the Firebase project has not yet been provisioned.

## 6. Why C1 Was Raised

**C1 is a legitimate CRITICAL finding — correctly classified.**

The production readiness review fork confirmed the files are absent:
- `apps/mobile/android/app/google-services.json` — NOT FOUND
- `apps/mobile/lib/firebase_options.dart` — NOT FOUND
- `apps/mobile/ios/Runner/GoogleService-Info.plist` — NOT FOUND

Without `firebase_options.dart`, `Firebase.initializeApp()` in `main.dart` has no `DefaultFirebaseOptions` to reference — the Flutter build fails at compile time. This is not a runtime gap; it is a build blocker.

C1 is correctly CRITICAL (not reclassified) because:
1. Mobile app cannot be built without `firebase_options.dart`
2. FCM is a required feature per approved architecture and API specification
3. All push notification business rules (leave, regularization, attendance reminders, account events) are dead without FCM
