## Critical Findings

### C1 — api_endpoints_test.dart: Invalid Dart Import (NEW — introduced by branding)

**File:** `apps/mobile/test/core/constants/api_endpoints_test.dart:2`

```dart
import 'package:com/genesis/system/core/constants/api_endpoints.dart';
```

**Problem:** The branding agent attempted to update the old import `package:company_mobile/core/constants/api_endpoints.dart` but used the Android `applicationId` format (`com.genesis.system` with dots replaced by slashes) instead of the Dart package name (`genesis_workforce`). This import is syntactically invalid — `com` is not a registered package and the path is nonsensical. Dart will throw a `Target of URI doesn't exist` compile error.

**Correct import should be:**
```dart
import 'package:genesis_workforce/core/constants/api_endpoints.dart';
```

**Impact:** This test file fails to compile. `flutter test` aborts for this file.

### C3 — Firebase Android: Google Services Gradle Plugin Not Applied + google-services.json Missing (Pre-existing, Production Readiness C1)

**Files:**
- `apps/mobile/android/app/build.gradle.kts` — no `id("com.google.gms.google-services")` plugin
- `apps/mobile/android/build.gradle.kts` (root) — no `com.google.gms:google-services` classpath
- `apps/mobile/android/app/google-services.json` — MISSING

**Problem (two parts):**

1. `apps/mobile/android/app/build.gradle.kts` does not apply the Google Services plugin. The `firebase_core` Flutter plugin for Android requires this plugin to process `google-services.json` and generate `google-services.xml` resources at build time.

2. `google-services.json` has never been generated (requires a live Firebase project + `flutterfire configure` or manual download from Firebase Console).

**Impact:** Android Gradle build fails. Even without the plugin issue, `Firebase.initializeApp()` in `main.dart:22` uses the native-config approach (no `options:` parameter), meaning it reads from `google-services.json` at runtime — which doesn't exist.

**Resolution path:** Provision Firebase project → download `google-services.json` → place at `android/app/` → add plugin to both `build.gradle.kts` files → rebuild.

---

### C4 — Firebase iOS: GoogleService-Info.plist Missing (Pre-existing, Production Readiness C1)

**Problem:** `Firebase.initializeApp()` in `main.dart:22` (no options) reads `GoogleService-Info.plist` natively on iOS. File was never generated.

**Impact:** iOS app crashes on launch at `Firebase.initializeApp()`.

**Resolution path:** Same Firebase project provisioning as C3 → download `GoogleService-Info.plist` → place at `ios/Runner/`.

## High Findings

### H1 — AndroidManifest: ACCESS_FINE_LOCATION Permission Missing

**File:** `apps/mobile/android/app/src/main/AndroidManifest.xml`

No `<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>` declared. The `geolocator` package (GPS for geofence check-in) requires this permission at runtime. Without it, `Geolocator.getCurrentPosition()` throws a `PermissionDeniedException`. Geofence-based attendance check-in is completely non-functional.

---

### H2 — AndroidManifest: READ_PHONE_STATE Permission Missing

**File:** `apps/mobile/android/app/src/main/AndroidManifest.xml`

No `<uses-permission android:name="android.permission.READ_PHONE_STATE"/>`. Device fingerprint computation reads `serialNumber` via `device_info_plus`. On Android 26+, `Build.getSerial()` requires `READ_PHONE_STATE`. Without it, `serialNumber` returns `Build.UNKNOWN` — device fingerprint is incomplete, causing potential AUTH_005 mismatches on login.

---

### H3 — iOS Info.plist: NSLocationWhenInUseUsageDescription Missing

**File:** `apps/mobile/ios/Runner/Info.plist`

`NSLocationWhenInUseUsageDescription` key is absent. iOS requires this string before displaying the location permission prompt. Without it, any call to `Geolocator.requestPermission()` crashes with an `NSInternalInconsistencyException`, and the App Store will reject the build during review.

---

### H4 — iOS Info.plist: NSLocationAlwaysAndWhenInUseUsageDescription Missing

**File:** `apps/mobile/ios/Runner/Info.plist`

`NSLocationAlwaysAndWhenInUseUsageDescription` key is absent. Required alongside H3 for complete location permission declaration on iOS. App Store submission will be rejected.

---

### H5 — FcmService: platform Hardcoded as 'android'

**File:** `apps/mobile/lib/features/notifications/data/services/fcm_service.dart:44`

```dart
'platform': 'android',
```

The FCM token registration POST body sends `platform: 'android'` unconditionally. iOS builds will register the wrong platform, causing incorrect token routing on the backend (`FcmToken.platform` will be `'android'` for iOS devices). iOS push notifications will fail.

**Fix:** Use `Platform.isAndroid ? 'android' : 'ios'` from `dart:io`.

## Root Cause Analysis

### C1 + C2 — Test import breakage (branding finalization gap)

The branding agent searched `apps/mobile/lib/` for `package:company_mobile` and found zero results (all lib files use relative imports — correct). It concluded "No `package:company_mobile` imports found." However, `apps/mobile/test/` was not included in the search. All 12 test files that use absolute imports still reference `package:company_mobile/...`.

For `api_endpoints_test.dart` specifically, the branding agent incorrectly updated the import to `package:com/genesis/system/...` — applying the bundle ID (`com.genesis.system`) as if it were a Dart package path. Dart package names use `snake_case` identifiers (`genesis_workforce`), not dot-separated reverse-domain notation.

**Impact:** 97 tests were passing before branding. After branding, 0 tests compile.

### C3 — Gradle plugin gap

The Flutter project was scaffolded without Firebase Gradle wiring because `flutterfire configure` was never run. Firebase packages were added to `pubspec.yaml` manually (which gets the Dart-side dependencies) but the Android native Gradle setup (plugin + JSON) requires either `flutterfire configure` or manual Gradle configuration. Neither was done.

### C4 — GoogleService-Info.plist gap

Same root cause as C3 — Firebase project never provisioned.

### H1–H4 — Permissions gaps

Android and iOS permissions are not auto-declared by Flutter or any plugin. They must be added explicitly to `AndroidManifest.xml` and `Info.plist`. The original scaffolding omitted them; no phase remediated this.

### H5 — Hardcoded platform

`fcm_service.dart` was written for Android-first as per the approved spec (`Platform: Flutter · Android-first · FCM`). The platform value was hardcoded during initial implementation and not made conditional for future iOS builds.
