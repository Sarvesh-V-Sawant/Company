## 1. Findings Resolved

### H1 — GET /employees: paginated response envelope double-wraps
**Severity:** HIGH → RESOLVED

**Root cause:** `EmployeeService.list()` returns `{ data: [...], meta: {...} }`. Route called `success(result)`, nesting the whole object under `data`.

**Fix applied (`src/app/api/v1/employees/route.ts:31`):**
```typescript
// Before (broken):
return success(result);

// After (spec-conformant):
return NextResponse.json({ success: true, data: result.data, meta: result.meta });
```

Response now matches spec §4.1:
```json
{
  "success": true,
  "data": [...],
  "meta": { "page": 1, "limit": 20, "total": 5, "totalPages": 1 }
}
```

---

### M3 — `registeredDevice.platform` hardcoded to `'android'`
**Severity:** MEDIUM → RESOLVED

**Fix applied — two files:**

`src/validators/employee.ts` — added `platform` field to `RegisterDeviceSchema`:
```typescript
platform: z.enum(['ios', 'android']).default('android'),
```

`src/services/EmployeeService.ts` — `registerDevice()` now accepts `platform` as optional final param (defaults `'android'` for backward compatibility):
```typescript
static async registerDevice(
  id: string,
  deviceFingerprint: string,
  deviceName: string | undefined,
  performedBy: string,
  platform: 'ios' | 'android' = 'android',
)
```

`src/app/api/v1/employees/[id]/register-device/route.ts` — passes `parsed.platform` to service:
```typescript
const result = await EmployeeService.registerDevice(
  id,
  parsed.deviceFingerprint,
  parsed.deviceName,
  payload.userId,
  parsed.platform,
);
```

Admin can now specify `"platform": "ios"` or `"platform": "android"` in the request body; defaults to `"android"` if omitted.

---

### M4 — `AppError('AUTH_006', 403)` missing message
**Severity:** MEDIUM → RESOLVED

`src/services/EmployeeService.ts` — both `list()` and `getById()` (same one-liner, replaced all):
```typescript
// Before:
throw new AppError('AUTH_006', 403);

// After:
throw new AppError('AUTH_006', 403, 'Forbidden.');
```

Employee-role callers now receive `{ success: false, code: 'AUTH_006', message: 'Forbidden.' }` instead of empty message.
