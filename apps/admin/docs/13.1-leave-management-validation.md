## 6. Findings

### HIGH

#### H1 — CRON Routes Have No Authentication
**File:** `src/app/admin/cron/leave-year-allocation/route.ts`, `src/app/admin/cron/leave-carryforward-expiry/route.ts`, `src/app/admin/cron/session-auto-close/route.ts`
**Detail:** All three cron routes execute with zero authentication. The Next.js middleware file (`src/middleware.ts`) was deleted in a prior phase. The replacement `src/middleware/cronGuard.ts` is a placeholder that throws `Error('Not implemented')`. There is no `CRON_SECRET` header validation, no `getAuthUser()` call, and no IP allowlisting. Any caller who knows the path can trigger allocation, expiry processing, or session auto-close.
**Risk:** Unauthorized annual leave allocation, unauthorized carry-forward expiry, unauthorized session mass-close.
**Fix required:** Implement `cronGuard.ts` to validate `Authorization: Bearer $CRON_SECRET` header (Vercel Cron sends this automatically); or restore Next.js edge middleware to protect the `/admin/*` path pattern.

---

### MEDIUM

#### M1 — LVE_005 Error Code Misassigned
**File:** `src/services/LeaveService.ts:274`, `:419`
**Detail:** In `approve()` and `reject()`, `AppError('LVE_005', 422, 'Only pending...')` is thrown for wrong-status validation. Per the implementation report, LVE_005 maps to LEAVE_NOT_FOUND. The actual not-found case uses `GEN_002`. LVE_005 is used for two semantically distinct error conditions.
**Fix:** Introduce `LVE_008` (or similar) for "wrong status" on approve/reject; reserve LVE_005 for leave-not-found or remove if redundant with GEN_002.

#### M2 — halfDayPeriod Dropped After Validation
**File:** `src/validators/leave.ts:11`, `src/app/api/v1/leaves/route.ts:31-38`
**Detail:** `ApplyLeaveSchema` validates and requires `halfDayPeriod: 'morning' | 'afternoon'` for half-day duration. The route's call to `LeaveService.apply()` does not pass `halfDayPeriod`. The `LeaveService.apply()` signature does not include it. The `Leave` model has no `halfDayPeriod` field. The value is validated then silently discarded. `AttendanceDay` receives `status: 'half-day'` with no morning/afternoon distinction.
**Fix:** Either (a) add `halfDayPeriod` to `LeaveService.apply` params, store in Leave model, and set on AttendanceDay; or (b) remove `halfDayPeriod` from validator if not required by spec.

#### M3 — getLeaveYearBoundaries Uses Local-Time Date Methods
**File:** `src/lib/utils/leaveUtils.ts:11-12`
**Detail:** `date.getFullYear()` and `date.getMonth()` return local server time. Dates are constructed as UTC midnight (`new Date(dateStr + 'T00:00:00Z')`). On servers in negative UTC offsets (e.g. UTC−5), January 1 UTC midnight = December 31 local time → `leaveYear` off by one year.
**Fix:** Replace `date.getFullYear()` → `date.getUTCFullYear()` and `date.getMonth() + 1` → `date.getUTCMonth() + 1`.

#### M4 — Leave Withdrawal Not Implemented
**Scope item:** "Leave withdrawal"
**Detail:** The 20-item scope explicitly includes "Leave withdrawal" as distinct from cancellation. `cancel()` implements `pending → cancelled` (employee cancels before admin reviews). Employee-initiated withdrawal of an *already-approved* leave (before the first affected date) is not implemented. There is no `'withdrawn'` status in `LeaveStatus` and no dedicated withdrawal endpoint.
**Fix:** Implement `LeaveService.withdraw()` for `approved → withdrawn` by employee, before first `affectedDate`. Must include balance restoration (same as revoke, but employee-initiated) and AttendanceDay revert.

#### M5 — LeaveBalanceService Has Zero Unit Tests
**File:** `src/services/LeaveBalanceService.ts`
**Detail:** `allocateLeaveYear()`, `processCarryForwardExpiry()`, and `creditCarryForward()` are untested. These are high-impact, year-boundary operations.

### LOW

#### L1 — reason Field: Optional in Validator, Required in Schema
**File:** `src/validators/leave.ts:11`, `src/models/Leave.ts:43`
**Detail:** `ApplyLeaveSchema` marks `reason` optional. `LeaveSchema` marks it `required: true`. The service uses `params.reason ?? ''` — an empty string passes Mongoose validation. Business intent likely requires a non-empty reason. No min-length constraint exists.
**Fix:** Either add `z.string().min(1).max(500)` to validator, or remove `required: true` from schema.

#### L2 — errors.ts Constants Outdated and Unused
**File:** `src/constants/errors.ts`
**Detail:** `LEAVE_001–LEAVE_005` constants predate the current `LVE_xxx` error code system and are not imported by any service or route. Dead code, potential confusion.
**Fix:** Remove `LEAVE_ERRORS` or update to match the LVE_xxx codes used by services.

#### L3 — Unused Model Fields (remarks on Leave)
**File:** `src/models/Leave.ts:17`
**Detail:** `ILeave.remarks?: string` is defined in interface and schema but never set by any service. May be a scaffold remnant duplicating `reviewRemarks`.
**Fix:** Remove `remarks` field if not required by spec.

#### L4 — restoration-rejection / restoration-cancellation Transaction Types Never Created
**File:** `src/models/LeaveTransaction.ts:9-11`
**Detail:** These types exist in the enum but no code path creates them (correct, since balance is not deducted at apply time, so rejection/cancellation require no restoration). Could mislead future developers.
**Fix:** Either remove from enum and add a comment explaining why, or document that they exist for potential future balance-at-apply variants.
