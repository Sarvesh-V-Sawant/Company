## 7. Findings

### HIGH

#### H1 — SystemEvent Idempotency Guard Missing from Cron Auto-Close

**Location:** `src/app/admin/cron/session-auto-close/route.ts`
**Spec:** TC-ATT-012 (Critical) — `docs/03-testing-strategy.md §3`
**Description:** The cron auto-close handler does not read or write the `systemEvents` collection before/after running. If Vercel retries the cron POST (standard platform behaviour), the second invocation will re-query `{ dateString, isActive: true }`. Because the first run already set `isActive: false`, the second run returns 0 results and is functionally safe. However, the testing strategy explicitly requires the SystemEvent guard as a Critical scenario. The `systemEvents` collection is defined in DB spec (§ `NEW v1.2`) and TC-ATT-012 verifies this behaviour.
**Required fix:** Before running, check `SystemEvent.findOne({ type: 'session-auto-close', dateString, status: 'success' })` → if found, skip and return early. After successful run, write `SystemEvent.create({ type, dateString, status: 'success' })`.

#### M2 — BR-ATT-05 (GPS Accuracy) Evaluated Before BR-ATT-04 (Geofence)

**Location:** `src/services/AttendanceService.ts:171–186`
**Spec:** BR-ATT-04 (geofence) is defined before BR-ATT-05 (accuracy). Current order:
```
nonce consumed → GPS accuracy → mock GPS → geofence
```
Spec order:
```
nonce consumed → geofence → GPS accuracy → mock GPS
```
**Impact:** When both conditions fail simultaneously, client receives ATT_002 (accuracy) instead of ATT_001 (geofence). Spec guarantees geofence error takes precedence. Test TC-ATT-017 notes nonce consumed before geofence but doesn't prescribe geofence vs accuracy ordering; however the spec BR numbering is unambiguous.
**Fix:** Move geofence check (lines 178–186) before GPS accuracy check (lines 171–173).

---

#### M3 — ATT_006 Mock GPS Enforcement Not Implemented

**Location:** `src/services/AttendanceService.ts:175–176`
**Spec:** BR-ATT-06 — "if settings disallow mock GPS → `ATT_006`"
**Current code:**
```typescript
const possibleMockGps = input.accuracy === 0;
// ATT_006 is never thrown
```
**Impact:** `ATT_006 (GPS_MOCK_DETECTED)` is defined in the error catalog but unreachable. A settings field to control mock GPS allowance (`geoFence.allowMockGps` or similar) was not added to `CompanySettings`.
**Fix:** Add `allowMockGps: boolean` (default `true`) to `CompanySettings`; if `accuracy === 0 && !settings.allowMockGps` → throw `ATT_006`.

#### M4 — `?employeeId` Query Param Missing from `GET /attendance/history`

**Location:** `src/validators/attendance.ts`, `src/app/api/v1/attendance/history/route.ts`
**Spec:** §5.4 — "employeeId | string | Admin only | Target employee (omit for own data)"
**Current state:** `AttendanceHistoryQuerySchema` has no `employeeId` field. Route always uses `payload.userId`. Admin cannot query another employee's history via this endpoint.
